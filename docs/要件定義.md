# 要件定義

最終更新: 2026年8月25日

---

## テーマ

季節のイベント・レジャー・グルメ・自然・癒しをより快適にするサービス

---

## ターゲット

高校生から20代前半の仲の良いグループで、季節のイベントやレジャーに行って共通の思い出を残したい人。

---

## 課題

1. 友達と遊びに行った後、**膨大な量の写真を確認するのが大変。**
2. 普通に写真を撮って友達と後から送り合うだけでは**味気ない。**

---

## 解決策

**そのイベントの全体像が一目で見えて、かつオリジナルの画像を簡単に作って共有できるようにする。**

- 撮る写真を**お題単位に最初から絞り込む**（スタンプラリー形式）ので、後から大量の写真をかき分けて探す作業自体が発生しない
- 手書き・スタンプで**その場でしか作れないオリジナル画像**を作って共有できる（デコる機能）

---

## MVP

これが動けば課題を解決したと言える最小の流れ。

```
Aが誘いを作る
  → 共有文をコピーしてLINEに貼る
    → Bがリンクを開く
      → 参加ボタンを押す
        → Aに参加者が見える
```

**この一本が通ればMVP成立。**
機能追加の提案が出たら「その機能がなくてもこの流れは成立するか」で判断し、成立するなら Should 以下に置く。

## 設計方針

- **インストール不要・アカウント登録不要のWebアプリ**とし、リンクを開くだけで使える形にする
- グループ作成を前提にせず、**投稿ごとに共有URLを発行**する（初回利用の障壁を下げるため）
- 生成文は**送信しない**。コピーして自分で手直しし、LINE等に貼る流れに留める
- 生成文は編集可能なテキストエリアで表示し、コピーボタンを付ける
- 生成文の末尾に共有URLを自動で含める

## 想定される質問への回答

### 「直接言えばいいのでは？」

直接誘うこと自体は自然にできるし、それで構わない。ただし、「行こう」と声をかけただけでは**誰が実際に来るのか正式に把握できず**、人数把握や日程の再確認を個別にやり取りする手間が残る。その部分（参加の意思表示・人数の可視化・当日の記録）を共有URLが肩代わりする。

「言うか言わないか」ではなく、**「言った後に何が残るか」**として説明する。

### 「既存サービスと何が違うのか？」

- **ウェザーニュース（花火の天気）** … 開催地と天気で完結しており、「誰と行くか」を一切扱っていない

#### 発表本番で使う3つの比較

- **既存の招待状サービス（パーティフル・ピアリー・ファボリ）** … 招待状を送るという点は似ているが、想定している場面が**結婚式や二次会など**で異なる。また招待状の作成に**アカウント登録が必要**になる
- **LINE** … 招待を送る手段としてはLINEに乗っかる前提でよい。ただしLINE自体は当日の記録を1つの成果物として残す仕組みを持たない。**送る手段はLINEでも、送った先でこのアプリを使う理由（スタンプラリーの記録＋デコる機能）がある**
- **Instagramのストーリー（デコる機能）** … 装飾できること自体は似ているが、**スタンプラリーとしての達成感**や、**実際にみんなで1つのものを作り上げる感覚**はInstagramにはない

#### その他の比較（発表では省くが、裏取り済みの回答）

- **調整さん・LINEスケジュールなどの日程調整ツール** … **ここは正直に役割が違うと認める。** 複数候補日から最適な1日を見つける精度では、これらの専用ツールに勝てない。このアプリは「日付がある程度決まった後」の招待・当日の記録を担当する立ち位置であり、日程調整そのものを置き換えるとは主張しない
- **GooseChase・PicCollageなどの写真ミッション系ツール** … 個別の機能（写真ミッション）だけを見ればどれかに代替されうる。ただし、①アカウント登録・導入コストなしで、②3〜5人の一回限りのカジュアルな集まりのためだけに、③その日専用の1枚の成果物として残せる、という3条件を同時に満たすツールは無い

**調整さんのような日程調整の専門ツールとは役割を分け**、それ以外のサービスとの**隙間**にある領域を狙っている。

### 「対象が狭いのでは？」

狭いのは対象ではなく、解いている**場面**。「声をかけてから、参加者が確定・記録されるまで」の一点に絞っている。対象自体は広い。

### 「日常の予定調整にも使えるのでは？」

使える。ただし説明は**季節イベント特化**で通す。汎用性を前に出すとテーマから外れ、LINEとの比較で不利になるため。拡張性は発表の「今後の展望」で触れる。

### 「高校生〜20代前半以外にも使えるのでは？」

使える。友人グループで思い出を形に残したいという構造は年齢を問わない。ただしピッチでは**高校生〜20代前半の季節イベント**という具体的な場面に絞って説明する。対象をさらに広げると生活スタイルの幅が大きすぎて説得力が薄まるため。それ以外の年代への拡張は「今後の展望」で触れる。

### 「継続的に使われるのか？」

頻度は低い。ただし**季節は毎年必ず巡る**ため、需要が消えることはない。

### 「アカウント機能はいらないのか？」

- MVPの流れ（作る→送る→開く→参加する）に登場しない
- 参加側の手数が増える。**「名前を入れて参加ボタンを押すだけ」まで参加ハードルを最小限に抑えた設計判断そのものを崩す**
- 認証で解けることは他の手段で解ける（一覧→localStorage、編集権限→編集トークン）
- 工数がMust級。**8/23のMust機能完成期限**（発表日8/28とは別）を圧迫する
- **デモで審査員にその場で参加ボタンを押してもらえなくなる**（登録が必要になるため）
